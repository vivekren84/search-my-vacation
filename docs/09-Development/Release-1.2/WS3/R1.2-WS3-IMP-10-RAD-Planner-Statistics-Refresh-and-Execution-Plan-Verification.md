### Task 3 — Verify planner choice, unwrapped (isolates each table/branch with real plan nodes)

```sql
explain (analyze, buffers, format text)
with normalized as (select public.immutable_unaccent(lower(trim('Kotagiri'))) as q)
select p.id,
  case when public.immutable_unaccent(lower(p.ascii_name)) like (select q from normalized) || '%' then 2.0
       else similarity(public.immutable_unaccent(lower(p.ascii_name)), (select q from normalized)) end as match_score
from public.geo_places p
where public.immutable_unaccent(lower(p.ascii_name)) like (select q from normalized) || '%'
   or public.immutable_unaccent(lower(p.ascii_name)) % (select q from normalized);

explain (analyze, buffers, format text)
with normalized as (select public.immutable_unaccent(lower(trim('Kotagiri'))) as q)
select a.geo_place_id
from public.geo_aliases a
where public.immutable_unaccent(lower(a.alias_text)) like (select q from normalized) || '%'
   or public.immutable_unaccent(lower(a.alias_text)) % (select q from normalized);
```

Look for `Seq Scan on geo_places` / `Seq Scan on geo_aliases` (confirms the planner is still not using the new indexes) versus `Bitmap Heap Scan` referencing `geo_places_ascii_name_unaccent_trgm_idx` / `geo_aliases_alias_text_unaccent_trgm_idx` (would mean the indexes are chosen and any remaining cost lies elsewhere). Please also capture the wrapped-function baseline for direct before/after comparison against this card's own cited baseline (4061.970 ms / `shared hit=14335`):
